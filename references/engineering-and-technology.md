# Engineering and Technology

Use this family when the deck explains systems, mechanisms, structures, experiments, technical capability, or engineering outcomes.

## Default Direction

`light-blue-system`

## Directions

### light-blue-system

- Best for: system design, technical explanation, engineering principles, project walkthroughs
- What it looks like: light blue base, strong module boundaries, architecture panels, process graphics, clear technical order
- Cover syntax: product render or configuration image plus stable title block
- Section syntax: numbered modules and explicit functional zoning
- Content grammar: architecture diagrams, module breakdowns, process flows, parameter tables, capability cards
- Preserve: structure, modularity, technical readability
- Avoid: overly cinematic dark atmospheres when the task is really about explanation

### deep-space-configuration

- Best for: aerospace, drones, robotics, payload, mission configuration, dark technical storytelling
- What it looks like: deep blue or near-black backgrounds, large hero images, mission-oriented panels, stronger scene feeling
- Cover syntax: strong hero image on dark background
- Section syntax: large number plus mission image
- Content grammar: configuration view, mission scene, performance highlights, task flow
- Preserve: scene impact and mission framing
- Avoid: overdecorating pages that should still present clear engineering facts

### white-lab-results

- Best for: experimental validation, benchmark reporting, test results, algorithm performance summaries
- What it looks like: white or very light base, result-first pages, charts and comparison tables with minimal theatrical framing
- Cover syntax: concise title with minimal instrumentation
- Section syntax: experiment-stage-oriented divider
- Content grammar: setup photo, curves, comparison tables, error analysis, findings page
- Preserve: chart space, quantitative clarity, lab realism
- Avoid: replacing experiment evidence with generic tech decoration
